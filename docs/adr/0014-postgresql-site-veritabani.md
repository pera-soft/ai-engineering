# ADR-0014 — `site` profilinde PostgreSQL: `org.postgresql:postgresql` (Faz 9d)

- **Durum:** Kabul edildi
- **Tarih:** 2026-10-22
- **Bağlam sahibi:** kullanıcı kararı (bağımlılık onayı 2026-10-22) + uygulayıcı kararları (aşağıda işaretli)

## Bağlam

Çok kullanıcılı site (ADR-0012) 50–60 kişinin verisini tutacak. H2 dosya DB'si tek süreçlik, yedekleme
ve işletme araçları zayıf (`pg_dump`, rol/yetki, uzaktan `psql` yok). Yerel (profilsiz) mod ve `mcp`
profilleri H2 ile sorunsuz çalışıyor ve öyle kalmalı.

## Karar

1. **Bağımlılık:** `org.postgresql:postgresql`, `runtime` kapsamı; sürümü Spring Boot parent yönetir.
   Başka yeni bağımlılık YOK — Flyway/Liquibase ve Testcontainers eklenmedi.
2. **`site` profili veritabanını YALNIZ ortam değişkeninden alır** *(uygulayıcı kararı)*:
   `SPRING_DATASOURCE_URL` / `_USERNAME` / `_PASSWORD`. `application-site.yml`'de URL'in varsayılanı
   YOK → değişken verilmezse uygulama açılmaz (canlı sessizce H2'ye düşemez); `config/SiteVeritabaniDenetimi`
   bunu hiçbir bean kurulmadan, anlaşılır mesajla yapar. Sürücü sınıfı URL'den
   çıkarılır (H2'ye sabitlenmez); yerel duman testi açık bir H2 URL'i verir. Yerel/`mcp` profilleri değişmedi.
3. **Tek, taşınabilir `schema.sql`** *(uygulayıcı kararı)*: aynı dosya H2 ve PostgreSQL'de idempotent
   çalışır (`spring.sql.init.platform` ile ayrı dosya GEREKMEDİ). Değişiklikler: `IDENTITY` →
   `BIGINT GENERATED BY DEFAULT AS IDENTITY`, `CLOB` → `TEXT` (H2'de `TEXT` = CLOB eş adı; mevcut H2
   dosyaları etkilenmez — `CREATE TABLE IF NOT EXISTS` atlar), PostgreSQL'de olmayan
   `ADD CONSTRAINT IF NOT EXISTS` → `CREATE UNIQUE INDEX IF NOT EXISTS` (hem yeni kurulum hem eski H2 DB). Göç
   aracı yok: şema ekleyerek büyür (`ADD COLUMN IF NOT EXISTS`), her açılışta yeniden çalışır.
4. **Tanımlayıcı tırnaklama kapalı** *(uygulayıcı kararı)*: Spring Data JDBC açık `@Table("KULLANICI")`
   adlarını tırnaklar; PostgreSQL tırnaklı büyük harfi ayrı ad sayar (`"KULLANICI"` ≠ `kullanici`).
   `config/JdbcAdlandirma` eşleme bağlamında `forceQuote=false` yapar → tırnaksız adları H2 büyük,
   PostgreSQL küçük harfe katlar; ikisi de şemayla eşleşir.
5. **Doğrulama Testcontainers'sız:** `SitePostgresEntegrasyonTest` yalnız `PG_TEST_URL` ortam
   değişkeni varken çalışır (`@EnabledIfEnvironmentVariable`); normal `./mvnw verify`'da atlanır.
   Her koşulda çalışan `SemaTasinabilirlikTest` şemada H2'ye özgü sözdizimini yakalar.
6. **Vekil arkası** *(uygulayıcı kararı)*: `server.forward-headers-strategy: native` (ADR-0012 §4) korunur;
   `SiteVekilBasliklariTest` gerçek Tomcat'te `X-Forwarded-Proto/Host`'un yönlendirmeyi
   `https://<alan-adı>/...` yaptığını doğrular. XSRF çerezi `guvenli-cerez=false` iken artık isteğe göre
   (https → Secure) yazılır; önceden düz `false`'a sabitlenirdi.

## Değerlendirilen alternatifler
- **Flyway/Liquibase:** sürümlü göç güzel, ama ek bağımlılık; şema küçük ve yalnız ekleyerek büyüyor,
  idempotent tek dosya yeterli. Şema yıkıcı değişiklik isterse yeniden değerlendirilir.
- **Testcontainers:** Docker şart değil (sunucu/geliştirici makinesinde garanti yok). Reddedildi.
- **Sitede H2 (dosya):** tek süreç kilidi, zayıf yedek/işletme. Reddedildi.
- **Platforma özgü iki şema (`schema-h2.sql` / `schema-postgresql.sql`):** iki dosya ayrışır; tek
  taşınabilir dosya mümkün olduğu için reddedildi.
- **`@Table` adlarını küçük harfe çevirmek:** tırnaklıyken H2'yi bozardı (H2 tırnaklı küçük harfi
  ayrı ad sayar). Reddedildi.

## Sonuçlar
- (+) Canlıda `pg_dump` ile yedek, rol bazlı en az yetki (`deploy/postgres-kurulum.sql.ornek`).
- (+) Yerel mod ve mevcut H2 dosyaları değişmeden çalışır.
- (−) PostgreSQL uyumluluğu CI'da otomatik değil; opt-in test elle koşulur (runbook'ta komut var).
- (−) `gorev_ilerleme` benzersizliği artık kısıt değil benzersiz indeks (`ux_gorev_ilerleme_kullanici`);
  ADR-0008 dönemi H2 dosyalarında eski `uq_gorev_ilerleme_kullanici` kısıtı da durur → aynı kolonlarda
  iki benzersiz yapı (zararsız, küçük tablo).
