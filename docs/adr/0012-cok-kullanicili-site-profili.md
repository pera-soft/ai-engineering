# ADR-0012 — Çok kullanıcılı eğitim sitesi: `site` profili ve kimlik (Faz 9a)

- **Durum:** Kabul edildi (9a + 9b + 9c + 9d uygulandı — 9c e-posta: ADR-0013, 9d PostgreSQL: ADR-0014; 9e açık — bkz.
  `docs/exec-plans/active/faz-9-cok-kullanicili-site.md`). 2026-10-22 güncellemesi: self-servis hesap silme
  KALDIRILDI (§9, §10).
- **Tarih:** 2026-10-22
- **Bağlam sahibi:** kullanıcı kararı (pera ekibi için site) + uygulayıcı kararları (aşağıda işaretli)

## Bağlam

AI Öğretmen tek kişilik, kimliksiz, yerel bir araçtı (`yerel` kullanıcı). pera'nın 50–60 backend
geliştiricisi aynı 12 haftalık programı bir eğitim sitesi gibi kullanacak: her biri kendi hesabıyla
girer, **yalnız kendi** ilerlemesini/quiz'ini/sohbetini görür. Kullanıcının kararları: e-posta + şifre
ile giriş, herkes kendi kaydolur ama **yalnız `@pera.software`**, yönetici paneli/sıralama yok, şirketin
tek OpenRouter anahtarı, kota yok. DB tabloları ADR-0008'den beri `kullanici_id` taşıyor ve kimlik
`KullaniciBaglami` arayüzünden geliyor — eksik olan kimliğin kendisiydi.

Başarısızlık ölçütü: bir kullanıcının başkasının verisini görmesi; pera dışından birinin kayıt olup
şirket anahtarını harcaması; **yerel modun bozulması**.

## Karar

### 1. Yeni Spring profili `site` (yerel mod değişmez)
- Profilsiz (yerel) mod **aynen** kalır: kimlik yok, `YerelKullaniciBaglami` = `yerel`, permitAll zinciri.
  Bu bean'lerin koşulu `!mcp-http` → `!mcp-http & !site` oldu. `mcp`/`mcp-http` dokunulmadı.
- `site` profilinde: `SiteGuvenlikYapilandirma` (config), `OturumKullaniciBaglami` (config),
  `KimlikService`/`KullaniciDetayServisi`/`GirisDenemeTakibi`/`EpostaGondericiSecimi` (service; 9c),
  `KimlikController` (web). Hepsi `@Profile("site")`. Ayarlar `application-site.yml` + `app.site.*`
  (`SiteAyarlari`).
- **Yeni bağımlılık YOK** — `spring-boot-starter-security` zaten vardı.

### 2. Kimlik = küçük harfli e-posta *(uygulayıcı kararı)*
İlerleme tablolarındaki `kullanici_id` doğrudan oturumdaki e-postadır (ör. `ali@pera.software`).
Gerekçe: ADR-0008'in JWT modu da e-postayı kimlik yapıyor — iki çok kullanıcılı mod tutarlı; ek
eşleme tablosu/join gerekmez; KVKK silme işlemi tek anahtarla yapılır. Bedeli: e-posta değişikliği
desteklenmez (şirket adresi; ihtiyaç doğarsa `UPDATE ... SET kullanici_id` ile taşınır).
`OturumKullaniciBaglami` **fail-closed**: oturum yoksa `IllegalStateException` — asla `yerel`'e düşmez.

### 3. Şema — `kullanici` + `kullanici_token` (taşınabilir SQL)
`kullanici(id, email UNIQUE, sifre_hash, dogrulandi, etkin, olusturma, basarisiz_deneme, kilit_bitis)`;
`kullanici_token(id, hesap_id → kullanici ON DELETE CASCADE, tur, token_hash UNIQUE, son_gecerlilik,
olusturma)`. H2'ye özgü `IDENTITY` yerine standart `BIGINT GENERATED BY DEFAULT AS IDENTITY`
(H2 + PostgreSQL ortak, 9d için). Yerel modda tablolar boş durur.

### 4. Giriş: Spring Security form login + sunucu tarafı HTTP oturumu
- `POST /api/kimlik/giris` (form: `email`, `sifre`, `_csrf`) → `/`; hata → `/giris.html?hata=<kod>`
  (`bilgi` = yanlış şifre/olmayan hesap — ayırt edilmez; `dogrulanmamis`; `kilitli`; `kapali`).
- `POST /api/kimlik/cikis` → 204 (oturum geçersiz, çerez silinir).
- Kimliksiz `/api/**` → **401** (JSON istemcisi yönlendirme izlemesin; `app.js` 401'de giriş sayfasına
  gider); sayfalar → `/giris.html`'e 302. Açık uçlar: giriş/kayıt/doğrulama sayfaları, `style.css`,
  `kimlik.js`, `POST /api/kimlik/kayit`, `GET /api/kimlik/dogrula`.
- Oturum çerezi `HttpOnly`, `Secure` (yerel http denemesi için `APP_SITE_GUVENLI_CEREZ=false`),
  `SameSite=Lax`; zaman aşımı 8 saat. Oturum sabitleme koruması Spring varsayılanı (giriş sonrası yeni
  oturum kimliği). Request cache kapalı (kimliksiz API çağrısı oturum açmaz).
- `server.forward-headers-strategy: native` — nginx'in `X-Forwarded-*` başlıkları yalnız güvenilen
  vekilden (127.0.0.1) kabul edilir (`framework` herkese güvenirdi).

### 5. Kayıt + e-posta doğrulama
- Yalnız `^[a-z0-9._%+-]{1,64}@pera\.software$` (kırpılmış, `Locale.ROOT` ile küçük harf; alt alan adı
  ve `pera.software.kotu.com` gibi sonek hileleri reddedilir). Şifre ≥ 10 karakter, ≤ 72 bayt (BCrypt
  sınırı), BCrypt (maliyet 10).
- Hesap `dogrulandi=false` açılır; doğrulanmadan giriş yok (Spring `DisabledException`).
- Doğrulama token'ı: 32 bayt `SecureRandom` (base64url), DB'de yalnız **SHA-256 özeti**, 24 saat,
  tek kullanımlık (kullanılınca/yeniden kayıtta hesabın tüm doğrulama token'ları silinir).
- **Hesap varlığı sızdırılmaz:** kayıtlı adrese yeniden kayıt da 200 döner; doğrulanmamışsa şifre
  güncellenip yeni bağlantı gider, doğrulanmışsa hiçbir şey değişmez.
- Gönderim `service/EpostaGonderici` arayüzünün arkasında. 9a'da tek gerçekleme `LogEpostaGonderici`
  (bağlantıyı INFO loglar). **9c (ADR-0013)** `SmtpEpostaGonderici`'yi bağladı; SMTP'siz `site`
  varsayılan olarak AÇILMAZ (`app.site.eposta-zorunlu`), log gönderici yalnız yerel denemede. 9c ayrıca
  "doğrulama e-postasını yeniden gönder" ve "şifremi unuttum" akışlarını ekledi (nötr yanıt, hız sınırı).
- Bağlantı kökü `app.site.temel-url` ayarından gelir, istek `Host` başlığından türetilmez (Host
  zehirlemesiyle sahte bağlantı üretilemesin).

### 6. Kaba kuvvet kilidi
Spring Security olayları (`AuthenticationFailureBadCredentialsEvent` / `AuthenticationSuccessEvent`)
`GirisDenemeTakibi` ile dinlenir. Yanlış şifre → `basarisiz_deneme + 1` (tek atomik SQL); 5'e ulaşınca
`kilit_bitis = şimdi + 15 dk` ve sayaç sıfırlanır. Kilitliyken doğru şifre de reddedilir (Spring ön
kontrolü şifreden önce çalışır → kilidi uzatmaz). Başarılı giriş sayacı/kilidi sıfırlar. Kalıcı
(DB'de) olduğundan yeniden başlatma kilidi kaldırmaz.

### 7. CSRF: Spring Security token AÇIK + mevcut Origin filtresi
- `CookieCsrfTokenRepository` (`XSRF-TOKEN` çerezi, HttpOnly DEĞİL, Secure + SameSite=Lax) +
  düz `CsrfTokenRequestAttributeHandler`. Statik ön yüz şablon motoru kullanmadığından token'ı
  çerezden okur: `app.js`'in tek `api()` yardımcısı (mulakat.js de onu kullanır) ve `kimlik.js`
  durum değiştiren isteklere `X-XSRF-TOKEN` başlığı, giriş formu `_csrf` gizli alanı ekler. Küçük bir
  filtre ertelenmiş token'ı her istekte yükler ki çerez ilk sayfada yazılsın. Login de CSRF'lidir.
- `web/CsrfKoruma` (Sec-Fetch-Site/Origin) ek katman olarak kalır; nginx arkasında origin
  `https://<alan-adı>` olacağından `app.site.izinli-originler` (env `APP_SITE_IZINLI_ORIGINLER`) ile
  birebir eşleşen origin'ler de kabul edilir. Liste boşsa (yerel) eski davranış.

### 8. Arayüz
Statik, Türkçe, CSP-temiz (inline betik/stil yok) sayfalar: `giris.html`, `kayit.html` (kısa KVKK
aydınlatması dahil), `dogrulama-bekleniyor.html`, `dogrulama-sonuc.html` + `kimlik.js`; görünüm
`style.css`'teki mevcut değişkenlerle. `GET /api/ozellikler` artık `{"mulakat":…, "site":bool}` ve
site modunda `"kullanici":"<e-posta>"` döner; `app.js` üst barda e-posta + **Çıkış** düğmesi gösterir.

### 9. Hesap kapatma — self-servis silme YOK (kullanıcı kararı, 2026-10-22)
Hesap silme/kapatma kullanıcıya açık bir özellik DEĞİLDİR. İşten ayrılan kullanıcının hesabını işletmen
(operatör) elle kapatır: `UPDATE kullanici SET etkin = FALSE WHERE email = '…'` (runbook 9d). Kapalı hesap
girişte `kapali` kodu alır; şifre sıfırlama/yeniden doğrulama bağlantısı da almaz.
Kapatma açık oturumlarda da ANINDA etkilidir (9d): `SiteGuvenlikYapilandirma.HesapEtkinlikFiltresi` her kimlikli
istekte hesabı yeniden okur; yok/`etkin=false` → oturum geçersiz, API 401, sayfa `giris.html?hata=kapali`.

### 10. Kişisel dosya verisi ve ortak modüller (Faz 9b) *(uygulayıcı kararları)*
- **Dizin şeması** (`service/KisiselDizin`): hafıza ve rapor önbelleği kullanıcı başına
  `<kök>/kullanicilar/<sha256-hex(kimlik)>/` (ör. `data/hafiza/kullanicilar/3f…/OGRENCI.md`,
  `data/raporlar/kullanicilar/3f…/hafta-01.md`). Özet sabit 64 hex → yol gezintisi/ayırıcı/ayrılmış ad
  (`kitaplar`) yapısal olarak imkânsız; e-posta dosya sisteminde düz görünmez (minimizasyon).
- **`yerel` = eski kök** (`data/hafiza/OGRENCI.md`, `hafta-NN/notlar.md`, `data/raporlar/hafta-NN.md`):
  yerel kullanıcının verisi TAŞINMAZ, göç adımı yok. Yerel sıfırlama yalnız `OGRENCI.md` + `hafta-*` +
  `hafta-NN.md` adlarını hedefler; `kullanicilar/`, `kitaplar/`, `vektor.json` korunur.
- Kimlik her işlemin başında BİR kez çözülür (hafıza güncellemesinde okunan ve yazılan dizin aynı kişinin).
  Silme yolları (`ogrenciNotlariniSil(id)`, `raporOnbeleginiSil(id)`, `SifirlamaService.sifirla(id)`) açık
  kimlik parametresi alır. Sıfırlama artık rapor önbelleğini de siler (yerelde de — eski ilerlemenin
  raporu temiz başlangıçta görünmesin).
- **`ai_kullanim.kullanici_id`** (ADR-0008'deki "DEĞİŞMEDİ" kararı burada değişti): `ADD COLUMN IF NOT EXISTS
  ... DEFAULT 'yerel'` (H2 + PostgreSQL), eski satırlar `yerel`. `SpringAiOgretmenClient` kimliği model
  çağrısından ÖNCE çözer (oturumsuz yol para harcamaz); `/api/kullanim` ve MCP `kullanim_istatistik`
  yalnız o kullanıcının satırlarını toplar (MCP kimliği açık parametreyle).
- **Sitede zorla kapalı:** kitap notu uçları (`KitapController @Profile("!site")` → 404), vektör deposu
  (`AnlamArama` no-op — anahtar olsa bile yüklenmez/indekslenmez), prompt'taki kitap bağlamı
  (`BaglamServisi`, `config/CalismaModu`); mülakat `MulakatEtkin` üzerinde `@Profile("!site")` —
  `APP_MULAKAT_ETKIN=true` sitede etkisiz, `/api/ozellikler` `mulakat:false`; MCP: `site` +
  (`spring.ai.mcp.server.enabled=true` | `mcp` | `mcp-http`) açılışta `IllegalStateException`.
- **Self-servis hesap silme KALDIRILDI (kullanıcı kararı, 2026-10-22):** 9b'de eklenen
  `POST /api/kimlik/hesabi-sil` + `HesapSilmeService` + üst bardaki "Hesabımı sil" düğmesi ve kayıt
  sayfasındaki "istediğin an silebilirsin" vaadi geri alındı. Ayrılan kullanıcının hesabı işletmen
  tarafından elle kapatılır (§9, `etkin=false`). `SessionRegistry` kaldı — artık şifre sıfırlamada
  (9c) kullanıcının bütün oturumlarını düşürmek için kullanılır.

## Değerlendirilen alternatifler
- **Kimlik = `kullanici.id` (sayı):** e-posta değişikliğine dayanıklı; ama ADR-0008 JWT modu e-posta
  kullanıyor, iki mod ayrışırdı; DB'de okunurluk ve KVKK silme kolaylığı kaybolurdu. Reddedildi.
- **Doğrulamasız kayıt (yalnız sonek kontrolü):** `uydurma@pera.software` ile şirket anahtarı
  harcanabilirdi. Reddedildi.
- **Yalnız Origin/Sec-Fetch-Site filtresi (Spring CSRF kapalı):** başlık göndermeyen istemcilerde
  fail-open (SECURITY.md); oturum çerezi olan bir sitede yetersiz. Token eklendi, filtre korundu.
- **XOR'lu (BREACH korumalı) CSRF işleyicisi:** statik sayfa çerezdeki ham değeri gönderdiği için ek
  karmaşıklık; yanıtlarda token yansıtılmadığından BREACH riski yok. Düz işleyici seçildi.
- **JWT/stateless oturum:** tek örnekli dağıtımda gereksiz karmaşıklık; çıkış/iptal zor. Reddedildi.
- **Bellek-içi kilit sayacı:** yeniden başlatmada sıfırlanır, DB'de zaten satır var. Reddedildi.
- **9b — dizin adı = arındırılmış e-posta (slug):** okunur ama e-posta diskte düz kalır ve arındırma
  kuralı çakışma/kaçış hatasına açık. **Yerel veriyi `kullanicilar/yerel/`e taşımak:** idempotent göç
  gerekir, kesinti anında yarım kalabilir; eski köke eşleme daha basit. İkisi de reddedildi.
- **Self-servis "hesabımı sil" (9b'de uygulanıp geri alındı):** kullanıcı istemedi (2026-10-22); şirket
  içi eğitim hesabı, ayrılışta işletmen kapatır (§9).
